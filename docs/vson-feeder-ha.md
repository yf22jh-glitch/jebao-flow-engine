# VSON SMART WP8621N Home Assistant 연동

`custom_components/vson_feeder`는 VSON SMART 앱 3.2의 WP8621N 경로에서 확인한 클라우드 API를 사용한다. HA 설정 → 기기 및 서비스에서 **VSON Smart Feeder**를 등록하면 온라인, 사료 부족, 사료 알림, 마지막 급여 시각·횟수, 즉시 급여 버튼이 생긴다. 현재 한 대는 HA `Aqua → 급여기` 뷰에 연결돼 있다.

급여 버튼은 `updateBleyFeed`를 한 번만 호출한다. 응답이 불명확해도 자동 재시도하지 않고, 10초 이내 중복 클릭은 거부한다. 대시보드 버튼에는 확인창을 붙였다. 급여 기록은 별도 `queryBleyFeedRecords` 조회값으로 표시하며, 급여의 물리적 배출량을 계측하지 않는다.

기기 자체 시간표 조회·수정 API도 구현돼 있다. 앱은 상태/급여에는 MAC을, 시간표에는 별도의 VSON cloud device ID를 사용한다. HA의 **설정 → 기기 및 서비스 → VSON Smart Feeder → 구성 → VSON 계정으로 급여기 찾기**에서 VSON SMART 앱 계정과 비밀번호를 입력하면, 계정의 기기 목록에서 등록된 MAC과 같은 장비의 ID를 찾아 시간표 조회까지 검증한다. 비밀번호와 계정명은 저장하지 않고, 장비 ID와 시간표 접근용 토큰만 HA private config entry에 저장한다. 토큰이 만료되어 시간표 조회가 실패하면 같은 화면에서 다시 로그인한다. 수동 ID 입력 경로도 남겨 두었다. 2026-09-29 실제 계정 연결 후 native schedule 9개를 오류 없이 읽었다([실기 기록](runs/2026-09-29-vson-feeder-account-discovery.md)). 슬롯 수정·삭제는 아직 실기 검증하지 않았다. 시간표 `week` 값은 앱의 원시 코드(`0`=1회, `1&2&3&4&5&6&7`=매일)다. 요일 숫자의 사람용 명칭은 이 코드에서 추정하지 않는다.

MAC·cloud device ID·계정 토큰은 저장소에 넣지 않는다. 실제 값은 HA의 private config entry에만 있다. 이 통합은 Jebao 펌프 제어 경로와 독립적이다.

실기 기록: [2026-09-29-vson-feeder-ha](runs/2026-09-29-vson-feeder-ha.md).

## 조회 오류 처리 (0.1.1)

상태·급여 기록·시간표를 각각 조회하고 캐시한다. 기록이나 시간표 조회가 실패해도
성공한 상태 센서는 유지된다. 각 조회 라운드가 끝난 뒤 30초에 다음 조회를 예약하며,
요청별 타임아웃은 12초다. 세 조회는 병렬이므로 한 요청의 지연이 다른 요청을 생략하지 않는다.
장비에 쓰는 급여·시간표 변경 요청은 자동 재전송하지 않는다.

각 센서의 `query_state`, `last_success`, `failure_since`, `recovered_at`,
`consecutive_failures`, `error_kind`, `http_status`, `endpoint`, `elapsed_seconds`로
조회 상태를 확인한다. 일시 실패는 `retrying`이며 마지막 성공값과 시각을 유지한다.
90초 동안 상태 조회 성공이 없으면 다음 조회 판정에서 상태 센서를 unavailable로 바꾸고
`Cloud status` 센서에 `클라우드 통신 장애`를 표시한다. 클라우드가 장비 오프라인을
명시적으로 보고한 경우에만 `급여기 오프라인`이다. 기록·시간표의 장기 실패는
`일부 조회 장애`로 구분하며 캐시에는 마지막 성공 시각이 계속 붙는다.

급여 버튼은 최근 상태 조회가 실패하면 비활성화된다. 기록 조회 실패만으로는 비활성화하지 않는다.
시작 시 전체 조회가 실패하면 HA의 통합 설정 재시도에 맡기고, 일부 조회만 성공하면
그 항목부터 표시한다. 실패·장애 전환·복구 로그에는 요청 파라미터, 원문 응답,
인증정보를 넣지 않는다. 대시보드는 각 항목의 재조회 여부와 마지막 성공 시각을 표시한다.

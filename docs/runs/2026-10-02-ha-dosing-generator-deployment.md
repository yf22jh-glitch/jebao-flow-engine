# HA 도징 자동 생성 편집기 배포

## 목적과 범위

하루 평균량 또는 N일 총량으로 도징 일정을 생성하고, 기존 HA 도징 제어를 보존한 채
미리보기와 저장·활성화 분리를 제공할 수 있는지 확인했다. 사용자의 구현·HA 배포 요청에
따른 서버와 UI 배포이며 실제 투여 실험이 아니다. 장비 설정 명령은 실행하지 않았다.

기준 HEAD는 `f83492fc5d6dcb70c2396f214fecc1f4a73dd8aa`이다. 배포 후보는 작업트리의
명시적 파일 목록으로 만든 이미지이며 HEAD 전체를 배포한 것이 아니다. 동결 하네스를
수정하지 않았고 원본 격리 작업트리는 건드리지 않았다. 기존 wire writer와 protocol은
교체하지 않았다. 별도 수류모터 실행기 컨테이너의 ID·이미지·시작 시각은 배포 전후 동일했다.

## 관측과 검사

- HA API로만 도징 화면의 `dosing_schedule_entity`와 두 module resource를 연결했다.
  `.storage` 직접 수정은 없었다. 새 entity 연결 필드만 제외하면 전체 dashboard가
  최초 백업과 동일하다. 기존 채널·보정 제어와 다른 여섯 view를 보존했다.
- 감사 당시 도징 sensor는 `idle`, active null, channels/templates/history 각 0,
  revision 5였다. 요청 다섯 건은 생성 미리보기뿐이며 저장·활성화·도징 송신은 하지 않았다.
  서버의 durable dosing 상태 파일도 비소유·비활성·기록 없음으로 확인했다.
- 같은 감사에서 GMP 실행기는 `active`, 현재 행 검증 true, last_error null이었다.
  이는 해당 시점의 실행기 보고이며 전체 기간 무고장을 의미하지 않는다.
- HA API 미리보기 확인: 하루 1.5mL → 2일 3회·1mL·16시간;
  하루 0.3mL → 10일 3회·1mL·80시간; 3일 30mL 3회 → 10mL·24시간;
  3일 30mL 한 번 → 지정일 30mL. 네 응답은 실행 출력으로 확인했으며,
  모든 개별 응답 raw를 보존했다고 주장하지 않는다.
- 실제 Orca HA에서 도징 편집기·원래 제어 화면이 렌더링되고 1.5mL 입력의 미리보기 버튼을
  눌러 1mL 세 건과 날짜·간격을 확인했다. 이 마지막 preview는 위 audit에도 보존됐다.
  활성화 버튼은 저장본 없음으로 비활성화였다. Orca 연결의 일시 장애 뒤 재접속하여 확인했다.
- 로컬 PC·390px 모바일 브라우저 테스트에서 저장/활성화 분리, revision 충돌,
  서버 응답 중 편집본 보존, 임의 HTML escape, 입력칸 경계 검사를 통과했다.
  초기 모바일 입력칸 겹침을 렌더링에서 발견해 수정했다. 서버 배포 asset HTTP digest도 일치했다.
- local-control·dosing 회귀 테스트 1,669개 통과. 이후 날짜 overflow 오류를 ValueError로
  변환하는 사례 추가 후 도징 관련 57개 통과. Ruff 및 diff 공백 검사 통과.
  구현 에이전트가 독립된 재독·회귀 검사를 수행했으며 별도 리뷰 에이전트는 실행하지 않았다.

## 새로 확정된 사실과 미검증 범위

HA 화면 → MQTT 생성 요청 → 운영 서버의 정확한 정수량·시각 계산 → HA 미리보기 표시가
동작한다. 기본 상태에서 외부 도징 일정은 실행되지 않으며 기존 제어 설정은 보존됐다.

새 외부 일정의 실제 투여와 완료 후 예약 소거는 이번에 검증하지 않았다.
실투여량은 보정·계량을 필요로 한다. 장치 슬롯은 매일 반복하므로 호스트·네트워크 장애로
소거되지 않으면 다음 날 재실행될 수 있고, 정리 대기는 물리 완료 센서가 아니다.
이 한계를 화면에 표시했다. 긴 기간의 평균 도징을 매일 소량 도징과 동등하다고 보장하지 않는다.

## 복구

서버 artifact에 이전 image·compose 입력을 보존했다. 외부 도징이 비활성이고 채널 소유가
없는 현재 상태에서만 이전 일반 제어 서비스로 복구한다. 활성 일정이 있다면 먼저 예약을
명시적으로 해제하고 확인해야 한다. 공유 hardware-safety 데이터와 별도 수류 실행기는
삭제·재생성하지 않는다. UI는 최초 artifact의 원래 도징 view와 module resource를 HA API로
복원한다. 최신 모바일 보완 artifact는 기능 도입 이전 백업이 아니라는 점을 구분한다.

## 최종 브라우저 확인 추가

최종 asset 재진입에서 HA 셸과 module은 로드됐으나 Orca 탭의 HA view 선택이 지연되어
빈 view container가 관측됐다. 브라우저 안의 도징 view만 다시 선택해 렌더링을 확인했다.
서버 설정이나 장비 명령은 변경하지 않았으며, 이 현상의 원인을 도징 코드로 판정하지 않았다.
최종 카드의 보완된 모바일 CSS, status idle, active null을 확인했다.
최종 실제 화면은 같은 최종 UI artifact의 `ha-live-dosing-final.png`로 보존했다.
SHA-256은 `5f90152bc3c3d3a76d97718c63d71138dc6cc0cdd10c9d01a75323dc48b51d20`이다.

## 채널을 먼저 선택하는 편집 화면 추가

사용자의 채널 선선택 요청에 따라 도징 편집 UI만 변경했다. 확인한 질문은
채널별 편집 화면을 분리하면서 다른 채널의 편집본과 운영 데이터를 보존할 수 있는가이다.
첫 화면에 채널 1~4를 표시하고 선택한 채널의 일정·생성 옵션·예약 상태·기록만 연다.
채널 전환은 송신 없이 입력을 유지한다. 빈 드롭다운은 채널 선택이 아니라 저장본 목록이었으며,
이제 별도 이름과 `저장된 시간표 없음` 표시를 둔다.

기존 서버의 여러 채널을 포함하는 템플릿 구조는 변경하지 않았다. 저장·활성화의 포함 채널과
전체 실행본 일시정지 범위를 화면에 명시했다. 채널별 독립 활성화 기능을 구현했다고 주장하지
않는다. 보정·펌프 제어·동결 하네스·일정 실행 코드는 수정하지 않았다.

- 구조화 배포 영수증 등급 (b): artifact `aqua-dosing-generator-20261002T094100Z`.
  UTC span `2026-10-02T09:41:00Z` → `2026-10-02T09:41:00.737139Z`.
  release SHA-256 `0d7dd0171f2975cae31301f3f2b917b4eff8ca0e0248e423dd4c138a27809223`.
  dosing module SHA-256 `3237fd04f29017f350168b8b1e13bc774e4af7bd49fe333309c591f066461057`.
  utility module은 앞선 배포와 동일하다. HA API 재조회에서 7개 view 설정 모두 동일하며
  HTTP asset digest를 확인했다. 기존 asset과 resource는 같은 artifact에 백업했다.
- 로컬 브라우저 검사: 초기 채널 선택, 비연속 행 인덱스 편집·삭제, 다른 채널 행 보존,
  채널별 생성 입력 유지, 늦은 타 채널 미리보기 응답 격리, 채널별 기록 필터,
  전체 템플릿 저장 payload, 390px 모바일 배치가 통과했다. UI fixture는 펌웨어 동작의
  증거가 아니라 화면과 요청 계약 검사다. 도징 단위 테스트 57개와 JS 구문 검사도 통과했다.
- 구현 에이전트가 수정한 선택·필터·저장·비동기 응답 경로를 재독했다. 별도 리뷰 에이전트는
  실행하지 않았다. 실제 HA에서는 채널 2 선택 후 제목과 생성 대상이 모두 채널 2이며
  pending false, dirty false, revision 5인 것을 확인했다. 이번에는 미리보기·저장·활성화도
  요청하지 않았다.
- 배포 전후 및 브라우저 선택 후 durable dosing 상태 파일 SHA-256은
  `7bca0147592d3b55a27e00b98f393b64a077c3e2892de302db3097b8cfc5bfb4`로 동일했다.
  revision 5, active null, channels/templates/history 각 0이었다. 이는 읽기 출력 확인이며
  별도 daemon raw artifact를 새로 수집한 것은 아니다. 일반 제어와 수류모터 실행기 모두
  컨테이너 시작 시각과 재시작 횟수 0을 유지했다.
- 실제 화면을 같은 artifact에 보존하고 원격 digest를 재확인했다.
  `ha-channel-picker.png`: `bd0f61031f21a286e294373b5b193b283c60a4903767d2cac9ef6d42e7499057`.
  `ha-channel-editor.png`: `c7fde5123d37f690ab96d69a47fd3463d900d8fb049c0ea4f555e62033f1a412`.
  재진입에서 앞서 기록한 HA view 선택 지연이 다시 보여 브라우저의 도징 view만 재선택했다.
  스크린샷은 UI 표시의 증거이며 물리 도징 성공을 증명하지 않는다.

현재 배포에서 채널별 편집 진입과 운영 데이터 보존은 확인했다. 실제 투여 및 예약 소거의
미검증 범위는 앞선 기록과 동일하다. 이번 UI만 되돌리려면 이 artifact의 이전 dosing asset과
resource 등록을 복원하며 도징 상태 파일이나 실행기는 변경하지 않는다.

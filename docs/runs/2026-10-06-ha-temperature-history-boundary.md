# HA 수온 그래프의 24시간 시작점 수정

## 목적과 확정된 원인

사용자가 보고한 그래프 왼쪽 공백이 기록 누락인지 표시 오류인지 확인했다.
HA의 기간 시작 상태와 렌더링 필터를 대조한 결과, 조회 이후 시간이 경과하면서
첫 상태를 범위 밖으로 제외하는 표시 오류였다. 시간축 전체가 이동한 것은 아니다.

읽기 전용 HA history 조회 구간은 `2026-10-05T07:37:46.640835Z`부터
`2026-10-06T07:37:46.640835Z`까지였다. 첫 반환 상태에는 구간 시작 시각의
수온 26.1°C가 있었고 다음 상태는 `2026-10-05T10:40:15.414196Z`의 26.0°C였다.
첫 상태를 버리면 약 3시간의 왼쪽 공백이 생긴다. 이 조회 출력은 등급 (c)의 관측으로
기록하며, 별도 원본 장비 프레임이나 HA 응답 파일을 보존했다고 주장하지 않는다.

기준 HEAD는 `7a035635fa10b9e6107c191b1617cd303579ba06`이다. 기존 작업트리의
overview 카드와 해당 테스트만 수정했다. 동결 하네스와 `src/`는 수정하지 않았다.

## 수정과 검증

`aqua-overview-card.js`는 현재 24시간 경계 직전의 가장 최근 상태를 경계에 유지한다.
이후 기록의 시각은 바꾸지 않으며 캐시 배열도 변경하지 않는다. 경계 이전 상태가
없는 경우에는 실제 기록 공백을 유지한다. 기록 생성이나 장비 설정 변경은 없다.

- 수정 전 고정 시계 테스트에서 조회 시작 상태가 렌더링 경계보다 1ms 앞서면
  첫 좌표가 `M125.0`으로 시작하는 실패를 재현했다. 수정 후에는 `M0.0`이다.
- 5분 캐시 경과, 가장 최근 경계 이전 상태 선택, 하루 동안 변화 없는 상태,
  실제 선행 기록 부재, 이후 점의 시각 보존 및 캐시 불변 검사를 통과했다.
- overview·return·utility·GMP schedule·bar schedule 카드 테스트 5개 파일,
  JS 구문 검사와 `git diff --check`를 통과했다. 구현 에이전트가 경계 처리와
  배포 범위를 재독했으며 별도 리뷰 에이전트는 실행하지 않았다.
- 실제 Orca HA 화면은 `2026-10-06T07:42:46.804Z`에 새 resource 버전을 사용했다.
  history 5개 상태의 첫 값은 26.1°C였고 SVG 경로는
  `M0.0 73.3 L123.3 86.7 L168.6 126.7 L357.1 86.7 L771.7 113.3 L1000.0 113.3`였다.
  화면 캡처에서도 왼쪽 끝부터 수온 선이 표시되는 것을 확인했다.
- 기존 Orca 재진입 관측과 같이 HA 셸에서 view 선택이 지연되어 overview를
  브라우저 안에서 다시 선택했다. 서버 설정이나 장비 제어로 우회하지 않았다.

## 배포와 보존 증거

기존 asset 배포 도구의 `--assets aqua-overview-card.js`로 단일 JS만 배포했다.
이전 asset과 resource를 백업하고 HA API로 resource 버전을 갱신했다.
HTTP asset digest와 dashboard API 재조회가 일치했다. 7개 view 설정은 모두 동일하고
31행 활성 시간표의 digest도 전후 동일했다. 장비 제어 요청과 재시작 명령은 0회다.

  `aa14fee1fd007769f4d0a47544f7d5d48fd40770eea8522377f95cd4b88108d5`.

운전 기간을 증명하지 않는다. 물리 장비 identity binding은 이번 UI-only 배포에 해당하지 않는다.

수온 기록, 엔티티, 장비 설정, 일정 실행기는 변경하지 않는다.
